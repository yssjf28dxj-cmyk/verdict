## Подготовленная среда

- Flutter 3.41.4, зависимости из существующего `pubspec.lock`.
- Java 21, Android SDK Platform 36, Build Tools 36.0.0.
- NDK 28.2.13676358 (версия из Flutter Gradle extension).
- Gradle 8.14 из закреплённого `gradle-wrapper.properties`.
- Android command-line tools загружены с Google и проверены по checksum
  официального repository XML; Gradle проверен по опубликованному SHA-256.

Инструменты и кэши находятся вне checkout, в `/workspace/.onboarding`.
Gradle использует существующий прокси среды (без записи паролей), четыре
рабочих потока и компиляцию Kotlin внутри процесса Gradle.

Команда из корня репозитория:

```sh
source /workspace/.onboarding/android-env.sh
flutter build apk --debug --no-pub --target-platform android-arm64
```

Это отладочная ARM64-сборка, не публикация и не выпуск в магазин.
Проверки на планшете и полного сценария авторизации/дебата/медиа ещё нет.

## Результат первоначальной попытки — 19 октября

APK **не собран**. После настройки Java-прокси устранён первоначальный сбой
получения Kotlin DSL plugin. Для Kotlin применён режим in-process, чтобы
не зависеть от неустойчивого запуска отдельного compile daemon в этой среде.

Далее Gradle остановился при конфигурации `flutter_plugin_android_lifecycle`:
Google Maven вернул HTTP 503 для зависимостей AGP 8.13.1, используемого
плагином: `com.android:signflinger:8.13.1`,
`com.android.tools.build:manifest-merger:31.13.1`,
`com.android.tools.build:apksig:8.13.1`. Повторная попытка Flutter завершилась
тем же результатом. Прямой curl-запрос signflinger POM также вернул 503
с сообщением о сбое upstream-соединения прокси. Альтернативный путь
`dl.google.com/android/maven2` вернул тот же код; `maven.google.com`
недоступен через текущий прокси.

Это подтверждённый блокер загрузки; сборка ещё не дошла до полной проверки
Android-приложения. Нельзя утверждать, что исходники полностью собираются
или что в них нет других ошибок. Версии зависимостей и проверки TLS не
менялись, сторонние зеркала не использовались. После восстановления доступа
повторить указанную команду: уже скачанные зависимости сохраняются в кэше.

Отсутствие отдельного тестового Firebase — другой, независимый блокер
безопасного запуска на планшете, а не причина ошибки сборки.

## Блокер безопасной проверки на устройстве

Текущая конфигурация указывает на Firebase `verdict-final`, а новые правила
и функции в него не публиковались. Сборка не запускает приложение и сама
не меняет пользовательские данные. Но такой APK нельзя выдавать за сборку,
изолированную от действующего Firebase.

Авторизованный доступ к Firebase CLI проверен командой `firebase projects:list`:
CLI сообщил `Failed to authenticate`. Существующих прав для создания и
настройки отдельного Firebase-проекта в этой сессии не установлено.
Пользователь сообщил, что отдельного тестового проекта нет или он неизвестен.

Следующий внешний шаг — создание отдельного тестового проекта через
https://console.firebase.google.com/. Никакие ключи или пароли не надо
отправлять в чат. Тестовые Firestore, Storage и Functions необходимо связать
с отдельной конфигурацией приложения, затем проверить её идентичность перед
установкой. Для облачных Storage/Functions может потребоваться тариф Blaze
и подключение биллинга; это отдельное решение владельца, не часть сборки APK.

Текущий Android application ID — `com.example.verdict`. Отладочная подпись
этой среды может отличаться от подписи APK на планшете; не удалять старое
приложение ради установки без отдельной проверки и сохранения нужных данных.
Для изолированной тестовой установки следует отдельно согласовать application
ID тестового варианта и его Firebase-конфигурацию.

## Продолжение — 20 октября 2026

Все три ранее недоступных Google Maven POM-файла при повторной проверке
вернули HTTP 200. Следующая попытка сборки обнаружила, что системная Java 21
содержит только runtime и не предоставляет `JAVA_COMPILER`.

В `/workspace/.onboarding/java` установлен полный Eclipse Temurin JDK
21.0.12.1+1 из официального GitHub release Adoptium; архив проверен по
опубликованному SHA-256. Системная Java не заменялась. В `android-env.sh`
и пользовательских свойствах Gradle выбран этот JDK. Для TLS используется
существующее системное доверенное хранилище сертификатов Java; проверка
сертификатов не отключалась. После этого сборка запущена повторно.

Повторная сборка завершилась успешно: `assembleDebug`, exit 0, 271.1 секунды.
Android-плагины дополнительно установили SDK Platforms 33–35, Build Tools 35.0.0
и CMake 3.22.1; основные compile/target SDK приложения — 36.

Проверки результата:

- APK: 146 956 252 байта; ZIP-архив без ошибок CRC.
- `apksigner verify`: подпись действительна, схема v2.
- Application ID: `com.example.verdict`, versionName `1.0.0`, versionCode `1`.
- Присутствуют разрешения INTERNET и RECORD_AUDIO.
- Команда задавала Flutter target `android-arm64`; наличие библиотек других
  плагинов для иных ABI не означает, что эти архитектуры проверены.
- SHA-256 APK: `fa1fc3b4bafba5af0205b737872ec3112afb17747c70326805da421f14d50795`.
- Android-исходники, Gradle-файлы проекта, манифесты зависимостей и lock-файлы
  не менялись для устранения проблем среды.

Сетевой блокер предыдущего дня и отсутствие компилятора Java устранены.
Отдельный тестовый Firebase и проверка работы на устройстве остаются
невыполненными. Существующий APK на планшете не удалять и не заменять этой
сборкой без согласования подписи, test application ID и Firebase-конфигурации.
