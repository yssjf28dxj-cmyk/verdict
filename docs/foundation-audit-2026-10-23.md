# VERDICT: проверка фундамента, 23 октября 2026

## Вывод

Продолжать развитие тестового MVP можно после согласованного обновления
сервера, правил и APK. Считать систему готовой к большой публичной нагрузке
пока нельзя: нет измеренного нагрузочного теста, проверки восстановимости
аккаунтов и полной миграции исторических данных/медиа.

Этот отчёт описывает проверенный исходный код в `codex/verdict-test-setup`.
Он не подтверждает публикацию новых исправлений в Firebase.
Скрипт deploy-test-server.sh теперь перенаправляет на согласованный foundation-выпуск. Рабочий проект
`verdict-final`, main и магазины приложений не менялись.

## Исправления

| Проблема | Изменение и проверяемая граница |
| --- | --- |
| Клиент мог обходить создание/принятие/удаление дебата через Firestore | Прямые lifecycle-записи запрещены; эти действия выполняют серверные обработчики. Проверяются поддельные сроки, участники, результаты и служебные поля. |
| Клиент мог изменять новые или старые поля рейтинга/статистики | Allowlist разрешает только редактируемые данные профиля. Публичный ID выдаётся сервером через транзакционный закрытый реестр; коллизии и старые дубли не перезаписываются молча. |
| Публичный профиль содержал email | Новый клиент хранит контактные данные в Firebase Auth. Правила запрещают добавлять/заменять email; разрешают убрать старую копию. **Старые копии требуют миграции ниже.** |
| Ранг GRANDMASTER давал административные права | Удаление, блокировки и очистка чата требуют boolean custom claim `admin: true`. Временный допуск к миграции этих прав не даёт. Служебные данные не читаются клиентом напрямую. |
| Устаревшая коллекция lobbies открывала непроверенный параллельный сценарий | Неиспользуемая коллекция закрыта для клиента; данные сохранены. Текущий LobbyScreen работает через debates и серверное принятие вызова. |
| Блокировку аккаунта можно было обходить в игровых действиях и заявках | Серверные изменения проверяют блокировку; прямые разрешённые запросы/модерация доступа также проверяют её в правилах. Отмена собственного ожидающего вызова остаётся доступной. |
| Поздний create-event мог перезаписать принятый ход | Инициализация читает актуальный документ внутри транзакции, игнорирует ожидание/завершение/отсутствующего оппонента и не заменяет уже установленный срок. |
| Повтор событий мог терять статистику при временной ошибке | Начисление использует существующий транзакционный маркер и повторяется при временной ошибке; повторное событие не начисляет второй раз. |
| Голос принимался после фактического срока, пока сервер ещё не переключил ход | Проверяется сам срок, активность раунда и ожидаемый клиентом номер раунда. Новые агрегаты обновляются атомарно с индивидуальным голосом. |
| Числовые метаданные могли попадать в итог голосования | Считаются только debate и существующие round_N. Сохраняется правило: голос за каждый раунд плюс отдельный голос за дебат. |
| Счётчик зрительских голосов оставался нулевым до конца | Новые дебаты используют 16 серверных счётчиков без UID голосовавших; клиент слушает их. Старые дебаты не объявляются автоматически мигрированными. |
| Ошибка запроса голоса оставляла кнопку заблокированной | Клиент снимает оптимистическую блокировку при обычной ошибке; уже принятый голос и номер раунда сверяются с сервером. |
| Ограничение частоты запросов жило в памяти одного экземпляра | Состояние перенесено в транзакционные серверные документы. Это ограничение на UID, не защита от массового создания новых анонимных аккаунтов. |
| Потерянный ответ World Chat мог приводить к повторному сообщению | Новый клиент повторяет тот же request ID; сервер атомарно сохраняет одно сообщение. Повтор ID с другим текстом отклоняется. Черновик не стирается при ошибке. Старый клиент без ID этой гарантии не имеет. |
| ИИ мог запускаться одновременно, принимать произвольного победителя и повторно начислять победу | Есть серверная аренда обработки, проверка UID/ключа победителя и конечных оценок 0–100. ИИ — отдельный совет; статистику определяет авторитетный результат боя. |
| Ошибка ИИ или отсутствие аргументов выглядели как ничья 50:50 | Явные состояния unavailable/insufficient_content/error; клиент не рисует выдуманные оценки. Ожидание ограничено. |
| Reasoning ИИ раскрывался на доступной карточке request-only дебата | Новые результаты хранятся в private_state/judgement с доступом как у переписки. **Старый корневой aiResult требует миграции.** |
| История профиля выбирала произвольные 20 документов, затем сортировала | Сортировка createdAt descending выполняется до limit; используются уже предусмотренные индексы. Старые записи без createdAt требуют отдельного восстановления метаданных. |
| Загрузка голоса обращалась через Storage Rules к другой базе | Новый ограниченный callable проверяет участника, блокировку, ход и срок в выбранной базе; принимает до 6 МиБ и пишет в закрытый uploads. Нужны новый сервер и APK. |
| Новый временный объект позволял SDK получить постоянную ссылку | Новая область uploads закрыта для SDK, включая получение metadata/download URL; публикация переносит файл в secured. Права повторно проверяются при отправке. |
| Удаление родителя оставляло дочерние документы Firestore | Административное удаление очищает дерево и допускает повтор после частичного сбоя. Storage-объекты намеренно не удаляются этим изменением. |

## Что именно проверено

- TypeScript собирается; unit-набор проверяет сроки, guards, путь медиа,
  идентичность профиля, ограничение запросов, допустимый AI-ответ и подсчёт голосов.
- Локальные Firestore/Storage Emulator: права ролей, приватность, конкурирующие
  транзакции, повторы событий, закрытие раундов без клиентов, голоса, блокировки,
  административные полномочия, выдача ID и полный путь байтов upload → send → download.
- Flutter: полный analyze, тестовые и production flavor-тесты. Тесты production
  проверяют изоляцию конфигурации, а не обращаются в рабочий Firebase.
- Добавлен CI без публикации и облачных секретов. Запуск GitHub Actions
  подтверждается только после выполнения workflow, не фактом наличия YAML.

Точные итоги последнего прогона и сборки записаны в конце отчёта. Эмуляторы
не проверяют реальный IAM, доставку Cloud Tasks, холодный старт, микрофон,
аудиокодек, скорость сети или сохранность нативной Auth-сессии на планшете.

## Подготовленный выпуск в тестовый проект

1. Сохранить установленное приложение и его данные: не удалять гостевые
   аккаунты, не нажимать Sign out для «возврата» в прежнюю личность.
2. На время согласованного обновления остановить ручное тестирование старого APK.
3. Из этой ветки в Cloud Shell выполнить `bash scripts/deploy-test-foundation.sh`.
   Скрипт жёстко выбирает verdict-test-1471f, базу default без скобок и проверяет
   существование тестового Storage bucket. Отсутствующий bucket надо сначала
   настроить в тестовом проекте; скрипт не создаёт его и не объявляет голос рабочим.
4. Проверить ACTIVE у новых функций и установить новый совместимый APK поверх
   старого с сохранением данных. Старый APK не получает новый интерфейс через Cloud Shell.
5. Проверить отчёт `node scripts/migrate-test-private-data.cjs`.
   Это dry-run: он читает только тестовый проект и показывает количества,
   не выводит email или тексты аргументов.
6. Перед изменением исторических приватных полей просмотреть отчёт и выполнить
   согласованную миграцию с `--apply`. Она сохраняет исходные значения в закрытом
   архиве и переносит AI в защищённый документ до удаления публичной копии.
   Она не меняет рабочий проект, не удаляет аккаунты или дебаты и не отзывает
   старые ссылки на медиа. До применения старую утечку нельзя считать закрытой.
7. Два независимых профиля: принять вызов, переключить роли без Sign out,
   отправить текст и голос, проголосовать зрителем, проверить итог и статистику.
   Закрыть оба приложения до истечения срока и проверить актуальный ход после возврата.

Административные инструменты после обновления требуют настоящий серверный
custom claim. Один только прежний rank=GRANDMASTER больше не открывает их.
Ключи, пароли и токены в чат не нужны.

## Незавершённое и границы масштабирования

- **На настоящем Firebase не проверено:** новый деплой, IAM, создание Storage,
  доставка задач, новый голосовой путь и новая миграция. Здесь нет облачных
  административных учётных данных владельца, поэтому эти действия не выполнялись.
- **Исторические данные:** email и корневой AI защищены полностью только после
  миграции. Старые token URL обходят правила; их отзыв/перенос требует отдельного
  плана совместимости и проверки конкретных объектов. Уже скачанные байты не отзываются.
- **Шесть профилей:** изоляция SDK предусмотрена, но сохранность всех шести
  личностей после перезапуска планшета требует проверки. Это инструменты теста,
  не восстановление аккаунта после Sign out/переустановки.
- **ИИ:** нужны отдельно настроенные GEMINI_API_KEY и GEMINI_MODEL. Они не
  добавлялись и не активировались автоматически. Ошибки/отсутствие конфигурации
  кешируются как явный результат; автоматического платного цикла повторов нет.
  Аренда исключает обычные параллельные вызовы, но не гарантирует единственный
  оплаченный запрос при аварии процесса после обращения к провайдеру.
- **Холодный старт:** minInstances=0 сохранён. Первый запрос может быть медленнее.
  Разогретые платные экземпляры без измерений и согласования не включались.
- **Нагрузка:** очереди, лимит 2 экземпляра, резервный проход 50 дебатов и чтение
  голосов при завершении требуют нагрузочного теста. 16 счётчиков не являются
  доказательством готовности к миллионам зрителей.
- **Злоупотребления:** ограничение UID и проверка банов не заменяют App Check,
  контроль создания анонимных аккаунтов, мониторинг затрат и защиту от спама.
  Бюджет Google Cloud уведомляет, но не останавливает расход.
- **Хранение:** авария между Storage и Firestore может оставить временный объект.
  Автоматическая очистка старых загрузок/неиспользуемых медиа и политика хранения
  ещё требуют реализации. Архив миграции и служебные лимиты тоже требуют retention.
- **Дизайн и новые функции:** визуальный план и шесть согласованных целей
  остаются в roadmap; этот пакет укрепляет основу, не заменяет их реализацию.
