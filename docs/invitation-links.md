# Приглашения по ссылке — тестовый пакет

## Статус

Подготовлено в тестовой ветке. Новый APK не собирали, Hosting не публиковали,
проверку на устройстве ещё не проводили. Установленный APK 4004 не получает
обработчик ссылок через обновление Cloud Functions.

Ссылка имеет вид `https://verdict-test-1471f.web.app/invite/DEBATE_ID`.
Копирование ссылки включается только для staging-сборки с
`--dart-define=VERDICT_INVITES_ENABLED=true`. До публикации тестовой страницы
кнопку не включаем. Это отдельный флаг от настройки Google-входа.

## Поведение

- Создатель ожидающего вызова может скопировать приглашение и отправить другу.
  Получатель сначала видит условия в существующем лобби и отдельно принимает их.
- При открытии приложение ждёт восстановления текущей сессии Firebase.
  Если пользователь не вошёл, приглашение ведёт к выбору входа или гостевого
  режима. После входа пользователь возвращается к тому же вызову.
- Разрешённый возврат из авторизации ограничен `/invite/ID`: внешний URL,
  произвольный маршрут, query, fragment и закодированные пути отвергаются.
- Знание ID не даёт дополнительных прав. Приватный вызов требует именно
  приглашённого аккаунта. Правила Firestore и `acceptDebateInvite` не ослаблялись.
  Ни роли, ни тексты сообщений, ни токены в ссылку не добавляются.
- Для закрытого чужого или удалённого вызова показано одно сообщение
  «Вызов удалён или недоступен этому аккаунту». При сетевой ошибке есть повтор.
  Завершённый бой открывает результат; отменённый вызов не восстанавливается.
- Кнопка отмены в лобби видна только создателю ожидающего вызова.
- Фоновый наблюдатель регистрируется после разрешённого чтения существующего
  вызова. Удаление документа и отзыв доступа снимают наблюдение вместо
  бесконечного ожидания или необработанного исключения.

## Android и браузер

Обработчики HTTPS App Links и `verdicttest://app/invite/ID` добавлены только
в staging-манифест. Действующий Android-манифест не получил тестовый домен.
При браузерном открытии статическая страница предлагает явную кнопку перехода
в тестовое приложение с указанием Android-пакета. Автоматических переходов нет.

Страница не запрашивает Firebase, не показывает тему или участников и не хранит
приглашение в аналитике. Она не является веб-клиентом дебатов. Интерфейс страницы
поддерживает русский и английский; тексты в приложении — семь языков.
После установки приложения нужно открыть ссылку ещё раз: отложенное открытие
после установки и Firebase Dynamic Links не используются.

`web/invitations/.well-known/assetlinks.json` связывает домен с пакетом
`com.example.verdict.test` и SHA-256 ранее проверенной подписи тестовых APK.
Перед передачей новой сборки обязательно сверить её фактическую подпись.
Верификация Android на настоящем домене локальным эмулятором не доказывается.

## Подготовленное развёртывание

`scripts/deploy-test-invitations.sh` фиксирует проект и сайт
`verdict-test-1471f`, проверяет Node.js 22 и конфигурацию, проверяет наличие сайта,
при необходимости создаёт только этот тестовый сайт и публикует только Hosting
из `firebase.invites.staging.json`. Скрипт не запускается автоматически вместе
с Functions, не публикует APK и не обращается к действующему проекту.

Порядок приёмки одного общего пакета:

1. Развернуть согласованный серверный пакет, нужный остальным обновлениям.
2. Опубликовать тестовую страницу указанным скриптом из Cloud Shell.
3. Проверить HTTPS 200 без перенаправления для `/.well-known/assetlinks.json`.
4. Собрать одну совместимую тестовую версию с флагом приглашений. Сверить пакет,
   подпись, версию и контрольную сумму перед передачей владельцу.
5. На устройстве проверить холодное и повторное открытие ссылки, возврат после
   гостевого/почтового входа, выбранный тестовый профиль и отказ чужому аккаунту.
6. Проверить Android App Links и браузерную кнопку, включая сценарий без
   установленного приложения. Публичные ссылки не распространять до приёмки.

## Локальные проверки

```sh
flutter analyze --no-pub
flutter test --no-pub --flavor staging
flutter test --no-pub --flavor production
node --test tests/invitations/*.test.mjs
node tests/invitations/run-hosting-tests.cjs
bash -n scripts/deploy-test-invitations.sh
```

Node.js 22 и зависимости `tests/firestore` нужны для Hosting-эмулятора. Он запускается
только на loopback с demo-проектом и временной копией настоящих статических файлов.
Проверяются HTTP-страница, MIME модулей и CSS, защитные заголовки и доступность
скрытого файла ассоциации Android. CI дополнен этими проверками.

Семь новых проверок Firestore используют настоящие обработчики сервера:
правильный/чужой приглашённый, запрет самопринятия и приёма без входа,
одновременное занятие одного места, повтор без перезапуска боя, отменённый
вызов и заблокированный приглашённый. Остальные проверки доступа к карточкам
и закрытой переписке остаются в общем наборе правил.

Отдельно локально выполнена задача Gradle
`:app:processStagingProfileMainManifest`: итоговый манифест содержит нужные
HTTPS/custom-scheme фильтры. APK этой задачей не выпускался.

Итоговый локальный прогон: анализатор без замечаний; 64 теста Flutter staging,
63 production с одним ожидаемым пропуском; 224 проверки Firestore/Storage;
4 проверки ссылок и конфигурации Hosting; 3 HTTP-проверки Hosting-эмулятора.
Синтаксис скрипта и workflow проверен `bash -n` и actionlint. Реальный запуск
GitHub CI не подтверждён; настоящее приложение и сайт ещё не обновлялись.
