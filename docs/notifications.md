# Уведомления: следующий тестовый пакет

Подготовлены серверная очередь, доставка через Firebase Messaging, регистрация
устройства, настройки и список событий внутри приложения. Код не развёрнут;
новой APK нет. Реальная FCM-доставка ещё не проверена. Серверные функции и
клиентский интерфейс включены только для VERDICT Test.

## Поведение

«Вызов принят» предназначено создателю, «Ваш ход» — текущему бойцу, «Бой завершён»
— обоим участникам. Уведомления по умолчанию выключены. Просмотр настроек и запуск
приложения не вызывают системный запрос разрешения. Он появляется после явного
включения или нажатия «Подключить на этом устройстве». При отказе следует разрешить
уведомления в настройках устройства и повторить подключение.

Переключатель хранит настройку аккаунта; разрешение ОС относится к устройству.
На другом устройстве того же аккаунта может потребоваться отдельное подключение.
Отключение настройки подавляет новые доставки всем устройствам аккаунта и снимает
привязку текущей установки. Смена тестового профиля и выход сначала дожидаются
снятия привязки. При сетевой ошибке они остаются в прежнем аккаунте и показывают
ошибку; повтор безопасен. Регистрация и смена личности выполняются последовательно. При возврате из фона
повторно проверяются системное разрешение и настройка аккаунта; отозванное
разрешение снимает привязку без нового запроса разрешения.
Событие обновления токена, пришедшее во время его первой регистрации, повторно
не снимает только что созданную привязку.

На экране блокировки показываются только VERDICT и общий тип события. Тема,
переписка, имя соперника и результат ИИ туда не копируются. Стартовый экран проверяет, что он ещё является текущим маршрутом, прежде чем
завершать свой отложенный переход. Поэтому открытый из уведомления бой не
перекрывается запоздавшей навигацией на главную. Нажатие проверяет UID,
формат указателя, тип события и срок действия, затем открывает защищённое лобби.
Уведомление не даёт новых прав и не переключает аккаунт или ход. Список событий
доступен из настроек; он показывает последние 50 записей и даёт обновить загрузку.
Просроченное событие не открывается; к старым боям можно вернуться через историю.

## Серверная схема

- `users/{uid}/private_settings/notifications`: приватная настройка; запись только
  через аутентифицированную функцию `configurePushNotifications`.
- `server_push_devices/{hash(token)}` и `server_push_installs/{hash(installationKey)}`:
  серверные привязки, закрытые правилами. Клиенту не раскрываются чужие токены.
- `server_notification_outbox/{hash(debateId, uid, eventKey)}`: стабильная запись
  события с состоянием доставки и списком уже обработанных устройств.
- `users/{uid}/notifications/{id}`: приватный список событий. Владелец может менять
  только отметку прочтения; создавать события или менять указатели не может.

Регистрация требует системного токена и случайного секрета установки. Секрет
сохраняется в закрытых настройках приложения; сервер хранит его хэш. Один токен
нельзя перепривязать, зная только токен другого устройства. Тот же секрет позволяет
снять старую привязку после смены профиля. Ротация удаляет прежний токен установки. Сохраняемый номер операции установки
и серверная запись снятия привязки не дают старому запросу после таймаута
восстановить регистрацию прежнего аккаунта. Такие записи не удаляются при выходе;
повторная регистрация использует более новый номер. При восстановлении старых
настроек клиент может согласовать номер с сервером, сохраняя ту же личность.
Максимум 20 актуальных устройств на аккаунт; регистрация ограничена частотой.
Устройства старше 30 дней без обновления исключаются, а при следующей регистрации
устаревшие записи очищаются. Невалидные FCM-токены удаляются после ответа FCM.

Триггер формирует стабильное событие и приватную запись транзакционно. Перед
отправкой повторно проверяются роль бойца, блокировка, настройка и состояние боя.
Устаревший ход, удалённый бой и отозванное участие подавляют доставку. Срок хода
ограничен его дедлайном и пятью минутами, принятия — пятью минутами, завершения —
сутками. Доставкой владеет временная аренда; ошибки транспорта оставляют повтор
доступным. Успешные устройства фиксируются отдельно при частичном сбое.

FCM/APNs не обеспечивают транзакцию с Firestore. Если процесс упадёт после
приёма сообщения FCM, но до записи подтверждения, повторная отправка возможна.
Android tag/collapse key, APNs collapse ID и дедупликация клиента снижают дубли;
абсолютная гарантия единственной системной всплывающей карточки не заявляется.
Приватный список событий содержит одну запись. Уже принятые ОС сообщения нельзя
отозвать транзакцией выхода; их текст остаётся общим, а открытие проверяет личность.

Срок действия — проверка приложения, а не настроенная Firestore TTL-политика.
Физическая очистка старых событий, очереди и неиспользуемых установок остаётся
задачей политики хранения перед массовым запуском.

## Платформы и развёртывание

Используется `firebase_messaging`; автоматическая инициализация отключена в
Android-манифесте и iOS Info.plist. Native Android проверен задачей обработки
манифеста без сборки APK. Клиентская логика общая для Android/iOS, но тестовая
Firebase-конфигурация пока Android-only. Для iOS ещё нужны отдельное тестовое
приложение Firebase, Apple Team/подпись, Push Notifications capability, APNs-ключ
в Firebase и проверка на настоящем устройстве. Эти настройки здесь не создавались.

Пять тестовых Functions добавлены в явный список `deploy-test-foundation.sh`.
Скрипт включает FCM API только для заданного VERDICT Test. Реальные разрешения
служебного аккаунта на отправку FCM проверяются при облачной приёмке; новые IAM
роли в этой работе не выдавались. Затем устанавливается одна согласованная APK
с прежней подписью, без удаления данных. Старый APK 4004 интерфейс не получает.

## Приёмка

1. Два разных аккаунта, разрешение дано/отклонено; просмотр настроек сам не спрашивает.
2. Принятие вызова, передача хода, завершение при открытом и свёрнутом приложении.
3. Запуск по уведомлению из завершённого приложения, другая текущая личность,
   устаревшее событие, удалённый/приватный бой.
4. Выход, быстрые переключения профилей, потеря сети, ротация токена и повторное подключение.
5. Два устройства одного аккаунта, отключение настройки и повтор события без дубля в списке.
6. Отдельно iOS/APNs после подготовки Apple-среды.

Эмуляторные проверки используют подставной отправитель: настоящие push-сообщения
и внешние сообщения в этой работе не отправлялись.

Локальная проверка 24 октября 2026: анализатор без замечаний, 72 серверных
теста, 306 проверок Firestore/Storage, 131 Flutter staging и 130 production
(один ожидаемый пропуск). Новые сценарии покрывают потерю ответа, частичный сбой,
снятие привязки до поздней регистрации, разрешения ОС, быстрые смены личности,
дедупликацию обновления токена и отложенную навигацию стартового экрана.
Android-задача `:app:processStagingProfileMainManifest` прошла; в объединённом
манифесте подтверждены POST_NOTIFICATIONS и отключённая автоматическая
инициализация. Это не сборка APK и не подтверждение реальной FCM-доставки.
