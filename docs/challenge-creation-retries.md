# Создание вызова при потерянном ответе

Подготовлено в исходниках 26 октября 2026 года. Ещё не развёрнуто и не включено
в установленный APK 4004. Сервер нужно обновить до передачи нового клиента.

## Поведение

Перед отправкой клиент сохраняет случайный clientRequestId и нормализованные
условия в SharedPreferences отдельно для каждого UID. Повтор тех же условий,
включая повторное открытие формы и ввод тех же значений, использует сохранённый ID.
Черновик формы автоматически из этой записи не восстанавливается. Изменённые
условия означают новое намерение и получают новый ID. После валидного ответа
исходная запись удаляется, если пользователь уже не создал более новое намерение.

Автоматического повторного запроса нет. Пользователь повторяет отправку сам.
Смена аккаунта до отправки блокирует вызов, а после ответа блокирует переход
в комнату предыдущего аккаунта. Ошибка и неправильный ответ сохраняют ID для
повтора. Ошибка записи локального ID не позволяет начать отправку.

Сервер проверяет условия обычным валидатором создания. Для запроса с ID он одной
Firestore-транзакцией создаёт дебат, серверную запись запроса и отметку ограничения
частоты. ID изолирован по UID; отпечаток включает тему, время, раунды, режим,
видимость, язык, регион и оппонента. Точное повторение возвращает прежний debateId
без нового ограничения частоты. Использование того же ID для других условий
отклоняется. Новые ID по-прежнему ограничены одним созданием за пять секунд;
ограничение общее с реваншем и старым методом создания.

Удалённый вызов не воссоздаётся. Если вызов уже отменён/принят/завершён, возвращается
тот же существующий дебат в его текущем состоянии. Блокировка аккаунта проверяется
и для точного повтора. Метрики создания начисляются только для нового дебата.

## Совместимость и доступ

APK 4004 без clientRequestId продолжает использовать прежний путь. Защита от
дублирования для старого бинарного клиента этим не добавляется. Старый сервер
не поддерживает новый контракт, поэтому одной клиентской правки недостаточно.

`server_create_requests` закрыт текущим запретом правил Firestore: читать или
подделывать запись не может даже её владелец. Запись содержит UID, debateId,
SHA-256 условий и createdAt; полный текст условий в неё не записывается.
Автоматическое удаление этих записей не включено. Перед массовым выпуском нужна
согласованная политика хранения; удаление записи при существующем отложенном
клиентском запросе ослабило бы защиту от дублей.

## Приёмка на устройстве

После обновления сервера установить согласованный новый APK поверх прежнего.
Потерять ответ уже отправленного создания, затем повторить те же условия:
в ленте должен остаться один вызов. Изменить условия и подтвердить новый вызов;
проверить ограничение частоты. Повторить со сменой тестового профиля, отменой,
закрытием формы и удалённым вызовом. Проверки с эмулятором не заменяют эту приёмку.

## Локальные проверки

После изменения прошли 72 серверных теста, все 321 проверки Firestore/Storage,
140 Flutter staging и 139 production с одним ожидаемым пропуском; анализатор
без замечаний. В составе прогонов: девять новых проверок реального createDebate
в эмуляторе и семь клиентских проверок сохранения ID, гонок и смены сессии.
