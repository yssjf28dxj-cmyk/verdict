# Шесть тестовых профилей на одном планшете

Временный инструмент только для Android staging (VERDICT Test).
Рабочая сборка production не показывает меню и не создаёт дополнительные аккаунты.

## Поведение

На главном экране справа находится меню «Профиль 1–6». Профиль 1 использует
существующее DEFAULT-приложение Firebase: текущий гостевой UID сохраняется.
Профили 2–6 используют именованные FirebaseApp verdict-test-profile-N с той же
конфигурацией тестового проекта. При первом выборе создаётся отдельный гость;
дальнейшее переключение не вызывает signOut. Firebase SDK сохраняет сессии
по отдельным именам приложений. В SharedPreferences записывается только номер
выбранного профиля, не токены, пароли или закрытые ключи.

Все профили используют verdict-test-1471f и именованную Firestore `default`.
Лента, World Chat и состояние дебатов общие; роль вычисляется по реальному UID
каждого аккаунта, а не по номеру профиля. Создателем остаётся создатель, соперником
соперник. Зрителю права бойца не выдаются. Сервер и Firebase rules не менялись.

Переключение доступно на главном экране. После успешной подготовки новой сессии
пересоздаётся дерево маршрутов: старые экраны и слушатели удаляются, наблюдение
за ожидающим вызовом очищается. Auth, Firestore, Functions и Storage получают
один и тот же выбранный FirebaseApp. Подготовка или сохранение выбранного слота
при ошибке не меняет текущую сессию; параллельные переключения блокируются.
При запуске восстанавливается выбор без создания нового гостя. Сбой восстановления
оставляет доступным прежний DEFAULT-профиль и записывается в диагностический лог.

## Ограничения

Это не постоянная система аккаунтов и не восстановление гостей после выхода.
Sign out по-прежнему выходит только из выбранного аккаунта и может потерять
анонимный UID. Удаление приложения/очистка данных также может потерять все
локальные гостевые сессии. Устанавливать обновление поверх, без удаления.
Очистка локальных данных, перенос между устройствами и привязка к почте сюда
не входят. Native FirebaseAuth persistence на планшете ещё нужно проверить.

Переключатель не моделирует два одновременно открытых устройства и их сеть.
Однако серверные таймеры продолжаются для всех профилей независимо от того,
какой сейчас открыт. Создание гостей ограничивается квотами Firebase Auth;
при ошибке новое переключение показывает сообщение и сохраняет старый профиль.

## Проверки

Семь тестов контроллера: сохранение выбранных идентичностей, восстановление
без нового гостя, запрет production, отказ подготовки, параллельные нажатия,
сбой записи выбора, диапазон 1–6. Это тесты управления переключением с подменой
Firebase-подготовки, не доказательство native SDK persistence или общих данных.
Для этих свойств требуется следующий тест на устройстве.

1. Обновить APK без удаления; убедиться, что имя бойца в профиле 1 не изменилось.
2. Создать вызов профилем 1, выбрать 2, принять и отправить текст в свой ход.
3. Вернуться в 1: свой боец сохранён, видны сообщения 2.
4. Выбрать 3: войти зрителем, проверить запрет сообщений и голосование.
5. Повторно пройти 1–6 и вернуться: аккаунты не должны создаваться заново.
6. Полностью закрыть приложение, открыть снова: выбранный профиль и его UID
   сохранены, дебат продолжает идти. Повторить с отключённой сетью и возвратом сети.
7. Проверить отмену ожидающего вызова только его создателем и отдельные
   уведомления/историю для каждого аккаунта.
